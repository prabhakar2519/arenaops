## Intentional exclusions
- Framework `/error` dispatch in both services: sanitized error bodies are documented as reusable components, not a business API.
- Login `TokenController.proxyRequest`: catch-all routing is delegation, not a finite resource endpoint; all documented Core resource paths can be called through the BFF with a session and identical verbs/bodies. It strips inbound Authorization/Cookie headers, adds the session Bearer token, refreshes once on upstream 401, and sanitizes downstream errors. No imaginary Core presence/public/legacy routes are added.
- Spring-generated HEAD/OPTIONS and Actuator endpoints are infrastructure, not ordinary customer operations. Core `/actuator/health/readiness` is public; Login readiness is public and proxies this check. Other Actuator endpoints follow the existing service security/exposure settings.

## Semantic audit limits and discrepancies
- Annotation metadata is reviewed against handlers, service validation, advice and security filters. Static/source/snapshot checks cannot prove that every rare runtime or dependency exception maps exactly as documented; no real Keycloak, PostgreSQL, SMTP, payment or live service calls were executed.
- Core FacilityFailure is a map with fieldErrors/conflicts (including empty collections); ordinary Core ErrorResponse omits nulls. Login adds optional conflicts to its error record and sanitizes downstream unknown/malformed bodies to a status-based code. Core concurrency errors may include CONCURRENT_CHANGE; ordinary Login errors do not.
- Global 404/405/406 responses are routing/negotiation outcomes rather than promises attached indiscriminately to every operation. HTTP 413 is documented for profile uploads. HTTP 422 is not implemented. Public facility check-in advertises HTTP 429 rate limiting.
- POST /api/academy/staff/{id}/invite is an exposed legacy handler whose service always rejects with STAFF_LOGIN_ACCESS_UNAVAILABLE after scope/resource checks; it has no advertised successful delivery response.
- Request optional reference-field nullability is annotated in existing DTOs, and facility PATCH null clearing is explicit. Response entity/reference-field nullability and state-dependent business fixtures still require field-level review; this is not claimed as exhaustive runtime schema verification.
- Known generator warning: springdoc 2.8.13 can log a non-fatal cloneViaJson/additionalProperties warning for map-valued schemas during repeated OpenAPI 3.1 requests. JSON/YAML and UI assets return HTTP 200, exports validate and snapshot drift checks pass; the warning remains unresolved and requires compatibility follow-up before claiming warning-free live documentation.
- Examples are synthetic and schema-derived except explicitly documented conflict/body examples. Replace IDs and temporary browser authorization codes with real authorized test fixtures; they are not executable onboarding credentials.

## Operational boundaries
Documentation is disabled by default; only the explicit local api-docs profile enables unauthenticated documentation access. Do not enable that profile on public/SIT/production deployments. Existing endpoint authorization is independent and unchanged. No Keycloak clients, passwords, realm roles or required actions were modified.
